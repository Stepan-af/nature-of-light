# Формы заявок

Все формы сайта отправляют данные в один обработчик — `public/api/send.php`. Разметка форм описана в `CLAUDE.md` → «Forms contract».

## Как это работает

```
<form data-lead-form action="/api/send.php"> ──► src/scripts/lead-form.ts ──fetch──► /api/send.php ──► e-mail (mail())
                                                  (проверка, маска, статусы)                          └► Telegram (Bot API)
```

### Клиент — `src/scripts/lead-form.ts`

- Подключается в компоненте формы: `<script>import '@/scripts/lead-form';</script>`. Можно подключать в нескольких компонентах на одной странице — каждая форма инициализируется один раз. Для динамически добавленных форм есть `initLeadForms(root)`.
- Проверка перед отправкой (те же правила, что на сервере):
  - поля с атрибутом `required` должны быть заполнены (чекбокс согласия — отмечен);
  - телефон — от 10 до 15 цифр (скобки, пробелы, дефисы не важны);
  - e-mail — корректный адрес;
  - должен быть заполнен телефон **или** e-mail;
  - длина: имя 100, телефон 30, e-mail 254, комментарий 2000, context 300 символов.
- Ошибки пишутся в `[data-error-for="<поле>"]`, у поля ставится `aria-invalid="true"` (снимается, как только поле исправляют).
- Маска телефона: при вводе с конца строки номер форматируется как `+7 (916) 123-45-67`; первая введённая 8 или 7 считается кодом страны. Маска не срабатывает при удалении, редактировании в середине и для номеров, начинающихся с `+` и другого кода страны.
- Отправка `fetch` (FormData, `Accept: application/json`). На форме переключается `data-state="submitting" | "success" | "error"`, текст — в `[data-form-status]`. Кнопки отправки блокируются на время запроса; после успеха форма очищается.
- События на форме: `lead-form:success`, `lead-form:error` (`event.detail.message`) — например, чтобы закрыть модальное окно.
- Таймаут запроса — 20 с, при сетевой ошибке показывается сообщение с просьбой повторить.

### Сервер — `public/api/send.php`

| Проверка | Ответ |
|---|---|
| не POST | 405 |
| нет `config.php` | 500 (в лог: `config.php is missing`) |
| Origin/Referer не из `allowed_hosts` и не текущий хост | 403 |
| тело > 64 КБ | 413 |
| заполнен honeypot `website` | 200 `ok: true`, ничего не отправляется |
| ошибки полей | 422 + `errors: { phone: "…" }` |
| превышен лимит (по умолчанию 5 заявок за 10 минут с IP) | 429 |
| ни один канал не настроен | 500 |
| все каналы не доставили | 502 |
| хотя бы один канал доставил | 200 `ok: true` |

Ответ всегда `{ "ok": boolean, "message": string, "errors"?: { [поле]: string } }`.

**Без JavaScript** (запрос без `Accept: application/json`) обработчик делает `303`-редирект обратно на страницу формы (Referer того же хоста) с `?sent=1` или `?error=1`. Страница может показать сообщение по этому параметру.

Поля: `source` (где форма: `home-faq`, `contacts`, `product:<id>`, `project:<id>`), `name`, `phone`, `email`, `comment`, `context` (скрытое поле с интересом клиента, например «Товар: …; Услуга: …»), `website` (honeypot). Всё, кроме пустых значений, попадает в письмо и сообщение Telegram вместе с адресом страницы и временем (МСК).

Совместимость: PHP 7.4 и 8.x, расширения не нужны (curl используется, если есть; иначе — `allow_url_fopen`).

## Настройка на хостинге

1. Скопируйте `api/config.example.php` → `api/config.php` **на сервере** (через файловый менеджер или FTP). В git `config.php` не попадает (`.gitignore`), автодеплой его не перезаписывает и не удаляет.
2. Заполните:
   - `allowed_hosts` — домены сайта (`prirodasveta.ru`, `www.prirodasveta.ru`);
   - `mail.to` — куда слать заявки (строка или массив), `mail.from` — ящик **на домене хостинга** (`noreply@ваш-домен`), иначе письма уйдут в спам или будут отклонены;
   - `telegram.bot_token` и `telegram.chat_id` (см. ниже);
   - `storage_dir` — папка вне корня сайта, доступная PHP на запись (для лимита запросов). Пусто — системная временная папка.
3. Канал можно отключить: `'enabled' => false`. Заявка считается отправленной, если сработал хотя бы один канал.

### Telegram

1. В Telegram откройте @BotFather → `/newbot` → получите токен вида `123456789:AA…`.
2. Добавьте бота в рабочую группу (или напишите боту сами).
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, отправьте сообщение в группу и найдите `"chat":{"id":…}` — у групп id отрицательный.
4. Впишите токен и id в `config.php`. Несколько получателей — массив `['-100…', '123…']`.

### Почта: `mail()` или SMTP

`mail()` работает на большинстве shared-хостингов «из коробки», но письма надёжнее доходят, если у домена настроены SPF/DKIM (обычно — в панели хостинга). Если хостинг запрещает `mail()` или письма теряются:

- включите в панели хостинга отправку через SMTP для PHP (у многих хостингов это настройка `sendmail_path`/«почта для скриптов»), или
- замените функцию `send_mail()` в `send.php` на отправку через SMTP (например, PHPMailer, загруженный рядом с `send.php`, с логином/паролем ящика в `config.php`). Контракт ответа менять не нужно.

Ошибки доставки пишутся в PHP error log хостинга с префиксом `[lead-form]` (без персональных данных).

## Локальная проверка

### Сейчас, без PHP (`astro dev`)

Dev-сервер Astro не выполняет PHP: на `POST /api/send.php` он отвечает 404/405 или отдаёт исходник файла. На `localhost` скрипт формы в этом случае **имитирует успешную отправку** и пишет в консоль браузера предупреждение `[lead-form] … simulating success` с отправленными данными. Так можно проверить весь UI: ошибки полей, маску, состояния `submitting/success/error`, сброс формы.

Проверка сервера без PHP невозможна — нужен PHP (см. ниже).

### С PHP (когда он установлен: `brew install php`)

```bash
npm run build
cp public/api/config.example.php dist/api/config.php
# в dist/api/config.php: 'allowed_hosts' => ['localhost:8080'], 'dry_run' => true
php -S localhost:8080 -t dist
```

Откройте http://localhost:8080/kontakty/ и отправьте форму. При `dry_run => true` ничего не отправляется, заявки дописываются в `<storage_dir>/leads-dry-run.log` (по умолчанию `$(php -r 'echo sys_get_temp_dir();')/prirodasveta-forms/`). Проверки из терминала:

```bash
# успешная заявка (JSON)
curl -i -X POST http://localhost:8080/api/send.php -H 'Accept: application/json' \
  -H 'Origin: http://localhost:8080' -d source=contacts -d name=Тест -d phone='+7 916 123-45-67'
# ошибка валидации → 422
curl -i -X POST http://localhost:8080/api/send.php -H 'Accept: application/json' \
  -H 'Origin: http://localhost:8080' -d phone=123
# чужой Origin → 403
curl -i -X POST http://localhost:8080/api/send.php -H 'Accept: application/json' -H 'Origin: https://evil.example' -d phone=9161234567
# без JS → 303 на Referer с ?sent=1
curl -i -X POST http://localhost:8080/api/send.php -H 'Referer: http://localhost:8080/kontakty/' -d phone=9161234567
```

Чтобы проверить реальную доставку в Telegram, выключите `dry_run` и заполните токен/чат (`mail()` локально, как правило, не работает — это нормально).

Помните: `php -S` не читает `.htaccess`, поэтому запрет доступа к `config.php`, кэш и редиректы проверяются только на Apache.
