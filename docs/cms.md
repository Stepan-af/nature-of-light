# Редактор сайта (Sveltia CMS)

Редактор открывается по адресу **https://prirodasveta.ru/admin/**. Всё содержимое сайта — товары, проекты, отзывы, контакты — хранится в репозитории на GitHub. Когда вы сохраняете изменения в редакторе, он делает коммит в репозиторий, после чего сайт автоматически пересобирается и публикуется примерно **за 2–4 минуты**.

## Вход

Нужен аккаунт GitHub с доступом на запись к репозиторию сайта (разработчик добавляет вас: репозиторий → Settings → Collaborators).

1. Откройте `/admin/` и нажмите **«Войти с помощью токена доступа»**.
2. Перейдите по ссылке в окне — откроется страница GitHub для создания токена с уже отмеченными правами. Укажите название (например, «Редактор сайта») и срок действия, нажмите **Generate token**.
3. Скопируйте токен (строка `ghp_…` или `github_pat_…`) и вставьте в окно редактора.

Токен хранится только в этом браузере. Не пересылайте его и не храните в открытом виде. Если токен истёк или утерян — создайте новый, старый удалите на странице GitHub → Settings → Developer settings → Personal access tokens. Для выхода: меню аккаунта (справа вверху) → «Выйти».

## Разделы

| Раздел | Что редактируется | Где на сайте |
|---|---|---|
| **Категории** | козырьки, навесы, зимние сады | карточки на главной, `/catalog/<категория>/` |
| **Товары** | карточки каталога | `/catalog/<категория>/<товар>/` |
| **Портфолио** | реализованные проекты | `/portfolio/`, блок проектов на главной |
| **Блоки страниц** | отзывы, вопросы и ответы, этапы работы, доп. услуги, преимущества | главная, «Услуги» |
| **Настройки сайта** | телефон, e-mail, адрес, часы работы, соцсети, цифры, реквизиты | шапка, подвал, «Контакты», «Реквизиты» |

## Как добавить товар

1. **Товары → «Создать товар»**.
2. Заполните **Название** — из него автоматически получится адрес страницы латиницей (например, «Козырёк Модерн» → `kozyryok-modern`). Адрес формируется при первом сохранении; позже его можно изменить в меню «⋮» редактора записи (редактор слага), но лучше не менять адреса опубликованных страниц.
3. Выберите **Категорию**, заполните материал, **цену «от»** (целое число без пробелов: `45000`), наличие.
4. Загрузите **Обложку** и заполните **Описание обложки (alt)** — коротко, что на фото.
5. **Галерея** и **Характеристики** — необязательно; элементы можно перетаскивать.
6. **Описание** — основной текст страницы.
7. **SEO** — можно не заполнять: заголовок и описание страницы сформируются автоматически.
8. Нажмите **«Сохранить»**. Через 2–4 минуты товар появится на сайте.

Чтобы временно скрыть товар или проект, включите **«Черновик»** — запись останется в редакторе, но не будет опубликована. **Порядок**: чем меньше число, тем выше карточка в списке.

## Как добавить проект в портфолио

**Портфолио → «Создать проект»**. Всё как у товара, плюс: метка на карточке («Зимний сад», «Терраса»), адрес объекта, город, год, площадь, срок монтажа, стоимость, **тип объекта** (частный/коммерческий — используется в фильтре) и переключатель **«Показать на главной»**.

## Фотографии

- Формат **JPEG** или **WebP** (PNG — только для графики), **не меньше 1600 px по ширине**, лучше 2000–2500 px. Горизонтальные кадры смотрятся лучше в карточках.
- Максимальный размер файла — 15 МБ. Редактор сам переведёт загруженное фото в WebP и уменьшит до 2400 px по длинной стороне; сайт дополнительно создаёт уменьшенные версии для телефонов.
- Названия файлов переводятся в латиницу автоматически.
- Фото хранятся в папке товара/проекта. При удалении записи её фото удаляются вместе с ней.
- Всегда заполняйте описание фото (alt): это важно для поисковиков и незрячих пользователей.

## Отзывы, вопросы, этапы и другие блоки

**Блоки страниц → нужный блок**. Элементы добавляются кнопкой «Добавить…», порядок меняется перетаскиванием, удаление — через меню элемента. В каждом блоке должен остаться хотя бы один элемент. Поле **ID** заполняется автоматически, не меняйте его.

Ответы в «Вопросах и ответах» поддерживают форматирование: жирный, курсив, ссылки, списки.

## Настройки сайта

**Настройки сайта → Контакты и общие данные**: телефон, e-mail, адрес, часы работы (формат «Пн–Пт 9:00–19:00, Сб 10:00–16:00» — из него же формируется разметка для поисковиков), ссылки на мессенджеры, цифры о компании и реквизиты. Незаполненные реквизиты на сайте не показываются.

## Если что-то пошло не так

- **Изменения не появились через 5 минут.** Возможно, сборка остановилась из-за ошибки в данных — сайт при этом остаётся в прежнем виде. Сообщите разработчику; он увидит причину во вкладке Actions репозитория.
- **«Ошибка при сохранении»** — проверьте интернет и срок действия токена, войдите заново.
- **Одновременная работа.** Редактор не рассчитан на одновременное редактирование одной записи несколькими людьми — договоритесь, кто что правит.

## Работа с локальной копией (для разработчика)

Позволяет править контент без GitHub-токена прямо в папке проекта — удобно, пока репозиторий не создан или для массовых правок.

1. Нужен **Google Chrome, Edge или другой браузер на Chromium** (Safari и Firefox не поддерживают доступ к файлам).
2. В папке проекта должен быть git-репозиторий (`.git`).
3. Запустите `npm run dev` и откройте **http://localhost:4321/admin/index.html** (именно с `index.html` — dev-сервер Astro не открывает `/admin/` без него).
4. Нажмите **«Работать с локальным репозиторием»** и выберите корневую папку проекта.
5. Правки сохраняются прямо в файлы `src/content/…`; результат виден на http://localhost:4321/. Коммит и push делаются вручную (`git`, GitHub Desktop).

После изменения `public/admin/config.yml` перезагрузите страницу редактора.

## Для разработчика

- **Репозиторий.** В `public/admin/config.yml` указан репозиторий `Stepan-af/nature-of-light`, ветка — `main`. Вход только по токену (`auth_methods: [token]`), OAuth-сервер не нужен. Для входа через кнопку «Войти через GitHub» понадобится OAuth-приложение и [Sveltia CMS Authenticator](https://github.com/sveltia/sveltia-cms-auth) (`base_url`).
- **Скрипт редактора** грузится с `https://unpkg.com/@sveltia/cms/dist/sveltia-cms.js` (всегда последняя 0.x). Если нужно зафиксировать версию — `@sveltia/cms@0.211.2`.
- **Схемы.** `public/admin/config.yml` должен повторять `src/content.config.ts`. После изменения любой схемы запустите:
  ```bash
  node docs/check-cms-config.mjs           # сверка полей, обязательности, enum, relation
  node docs/check-cms-config.mjs --schema  # + проверка по JSON-схеме Sveltia (нужен интернет)
  ```
- **Пустые необязательные поля не записываются** (`output.omit_empty_optional_fields: true`), потому что zod-схемы Astro принимают `undefined`, но не `null`. Следствие для `settings.json`, который импортируется напрямую: необязательные поля настроек (реквизиты `legal.*`, кроме `company`) могут отсутствовать в файле — в `src/lib/site.ts` они должны быть типизированы как необязательные.
- **Картинки** в бандлах сохраняются относительными путями без `./` (`cover.webp`) — Astro их понимает; существующие `./cover.jpg` тоже работают.
- **Иконки/OG-картинка**: `node docs/generate-brand-assets.mjs`.
